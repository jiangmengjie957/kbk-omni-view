## 修复 HistoryDrawer 删除 bug + 长期/非长期区分

- **Bug 根因**：HistoryDrawer 的"删除选中"/"清空全部"用 `Modal.confirm`（命令式），确认框渲染到 document.body，被 antd Drawer 高 z-index 遮挡 → 用户看不到确认框 → "点击没反应"。
- **修复**：改用 `Modal.useModal()` hook 模式，`modal.confirm` 在 `modalContextHolder` 附近渲染，不被 Drawer 遮挡。这是 antd 官方推荐的嵌套场景用法。
- **长期/非长期区分方案**：分 Tab（不是打标），只在消课表的 HistoryDrawer 显示两个 Tab：
  - "上传历史"（historyRecords，文件级，1年过期，可下载原始文件）
  - "长期消课单元"（lessonMonthlyRecords，月度单元级，不过期，按年月降序+学生升序排列）
  - perf-stats 页面的 HistoryDrawer 保持原样（不显示 Tab）
- 新增 `persistentLessonDb.ts` 的 `deleteMonthlyRecords(keys)` 与 `clearAllMonthlyRecords()` 函数（按复合主键删除/清空）
- 长期单元列表每条显示：学生姓名、年月 Tag、班型 Tag、节数总和、有课天数、保存时间；支持全选/勾选/删除选中/清空全部

## 修复 Dexie UpgradeError: Not yet support for changing primary key

- **原因**：v3 的 `lessonMonthlyRecords` 表用复合键 `[studentName+yearMonth+banXing]`，v4 改成 `yearMonth` 单键。Dexie 不支持在版本升级时改变已有表的 keyPath → 报 UpgradeError
- **修复**：v4 改用新表名 `monthlyRecords`（keyPath=yearMonth），v3 的 `lessonMonthlyRecords` 在 v4 stores 里没定义 → Dexie 自动删除旧表，新建 `monthlyRecords` 表。这是 Dexie 处理 keyPath 变更的标准做法（换表名让旧表自动废弃）
- 改动：
  - `src/db/index.ts` — class 字段 `lessonMonthlyRecords` → `monthlyRecords`；v4 stores 用 `monthlyRecords: 'yearMonth'`
  - `src/utils/persistentLessonDb.ts` — 所有 `db.lessonMonthlyRecords` → `db.monthlyRecords`（replace_all）
- `npm run build` 通过
- **踩坑教训**：Dexie 改 keyPath 不能直接在 stores 定义里改同表的 keyPath，必须换表名让旧表废弃。这是 Dexie 的硬限制。
