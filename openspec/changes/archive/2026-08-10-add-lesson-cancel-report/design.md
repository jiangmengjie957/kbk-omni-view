## Context

机构提供了一份真实消课表模版 `/Users/jiangmengjie/Downloads/jz/消课表.xls`，含三个 sheet：

- **`取值`**（用户上传的原始数据）：9 列 `日期/时段/科目/老师/次数/学员姓名/年级/班型/学生人数`，第 0 行即表头（无标题行），933 条数据。日期为 Excel 序列号（46143~46173 对应 2026-05-01~31），混入少量文本日期（`"2026.5.13"`、`":2026/5/30"`）。时段分隔符混用 `-`/`~` 与全角/半角冒号。次数列值为 `1` 或 `0.5`。班型写法多样：`1V1/1v1/一对一`、`1V3/1v3/一对三`、`1V6/一对六`、`小班`、甚至误填 `初三`。学生人数列与姓名拆分数偶有不一致（19/933）。
- **`消课时汇总表`**（目标产出）：行=学生×班型，列=序号/学生姓名/班型/1..31/汇总，首行有标题"X月课时汇总"跨列合并，其后表头行，再数据行。序号有跳号（14→15→16、70→72）说明是手工填的、应自动连续生成。
- **`Sheet3`**：空。

绩效统计页面（`src/pages/PerfStats/index.tsx`）已实现 SheetJS 上传 + 行级校验 + 聚合链路，可复用上传组件骨架与 `parseStudentCount`/`parseDurationHours`；但其导入表是 7 列 + 标题行结构、班型仅 `1V\d+`、节数来源是时段÷2，与消课表模版不同，故消课表独立实现解析。

技术栈：React 19 + Rsbuild + antd 5 + xlsx 0.18，前端纯静态，无后端。

## Goals / Non-Goals

**Goals:**

- 新增"消课表"菜单与页面，按真实模版"取值"sheet 结构解析
- 节数优先取"次数"列，缺失/非法时回退"时段"列 ÷ 2
- 班型归一化为 `1v1`/`1v3`/`1v6`，非标准值作为异常行跳过
- 跨月数据弹窗单选目标月份
- 异常行跳过统计，置顶 warning 告警面板列出行号/字段/原始值/原因
- 按学生×班型生成当月日期矩阵（1~当月天数），1v多课拆到每个学生各计该行次数
- 一键导出与"消课时汇总表"模版结构一致的 `.xlsx`

**Non-Goals:**

- 不持久化数据（刷新即丢，与绩效统计一致；Dexie 不升级 schema）
- 不计算课时费（绩效统计已覆盖）
- 不修改绩效统计页面现有行为
- 不做学生主数据管理或跨月对比
- 不做姓名归一化（空格/大小写差异由用户在源表统一）

## Decisions

### 决策 1：消课表独立实现解析，不强行复用 PerfStats 的校验函数

**选择**：消课表页面内联自己的解析与校验逻辑（或抽到 `src/utils/lessonCancel.ts`），不抽取 PerfStats 内联的 `excelSerialToDate`/`isValidExcelDate`/`isValidTime` 到共享。

**理由**：两个页面的导入表结构（9 列 vs 7 列）、表头位置（第0行 vs 第1行）、班型规则（归一化 vs 严格 `1V\d+`）、节数来源（次数列 vs 时段÷2）、校验项都不同。强行抽取共享会增加耦合，且消课表的需求未来可能再变。仅复用真正通用的纯函数：`parseStudentCount`（姓名拆分）、`parseDurationHours`（时段→小时数，需扩展支持 `~`）。

**替代**：抽取一套"课时统计表"通用校验——拒绝，因为两份表校验语义差异大，共享会漂移。

### 决策 2：节数取值"次数列优先，时段回退"

**选择**：每行节数 = `次数列`（E 列）若为合法正数则直接用；否则用 `parseDurationHours(时段) / 2`；两者都非法则该行作为异常行跳过。

**理由**：模版"次数"列是机构手工标的实际消课节数（1=整节、0.5=半小时节），是权威值。但样本中次数列与时段÷2 有 27 行不一致（如 `14:50-17:00` 标 1 但实算 2.16h，`9:00-10:00` 标 0.5 实算 0.5h 一致），说明"次数"列更贴合机构口径。回退到时段÷2 处理次数列缺失/非数字的边角情况。

**实现要点**：`resolveLessonCount(row)` 返回 `{ count: number, source: '次数列' | '时段推算' }` 便于告警面板展示来源。

### 决策 3：班型归一化映射

**选择**：`normalizeBanXing(raw)` 把班型字符串归一化：
- `1V1`/`1v1`/`一对一` → `1v1`
- `1V3`/`1v3`/`一对三` → `1v3`
- `1V6`/`一对六` → `1v6`
- `1V2`/`1v2`/`一对二` → `1v2`（样本中有 5 行，归一为 1v2）
- `1V4`/`1v4`/`一对四` → `1v4`（汇总表样本中有 4 行 1v4）
- `小班`、`初三`（误填到班型列）、其他非标准 → `null`（异常行跳过）

**理由**：汇总表样本显示机构习惯用 `1v1`/`1v3`/`1v4`/`1v6` 这几种归一化形式。归一化后聚合键稳定，避免同班型因大小写/中英文写法不同被拆成多行。

**实现**：先 `trim` + 转大写去空格匹配 `1V\d+` 抽数字；中文映射用查表；都不中则返回 null。

### 决策 4：1v多课拆行，每个学生各计该行次数

**选择**：一节 1v3 课次数=1，姓名列有 3 个学生，则拆成 3 行（每行该日该班型单元格 += 1）；姓名列只有 1 个学生但班型是 1v3，仍按 1 行计（次数=1）。

**理由**：消课表是按学生统计本月消课节数，每个学生上了一节 1v3 课就是消了 1 节。汇总表样本（彭少棋 1v3 在 5/16 与杨韵可同上 1v3，5/16 单元格对彭少棋=1、对杨韵可=1）验证此逻辑。

**人数列处理**：模版"学生人数"列与姓名拆分数有 19/933 不一致，**以姓名列实际拆分数为准**（与 PerfStats 现行逻辑一致），人数列仅作信息不参与计算。

### 决策 5：时段分隔符扩展支持 `~`

**选择**：`parseDurationHours` 当前支持 `-`/`—`，消课表模版时段用 `~`（如 `8:00~10:00`）和 `-`/`—` 混用。在消课表里扩展分隔符正则为 `/[-—~]/`，或在 `lessonCancel.ts` 内做预处理把 `~` 替换为 `-` 后调用原函数。

**理由**：最小改动复用现有函数。优先在 `lessonCancel.ts` 内预处理，避免改 `calcFee.ts` 影响绩效统计（虽然扩展分隔符对绩效统计也是兼容的，但本次不动 PerfStats）。

### 决策 6：日期解析兼容文本日期

**选择**：`parseDate(cell)` 优先按 Excel 序列号（number 且在合法范围）；若是 string 尝试用正则匹配 `(\d{4})[./\-](\d{1,2})[./\-](\d{1,2})` 解析为年月日；前导 `:` 等杂质字符先 trim 清理；都不中则该行作为异常行（原因"无法识别为有效日期"）。

**理由**：模版样本有 `"2026.5.13"`、`":2026/5/30"`、`"2026.5.3"` 等文本日期，能解析的应保留，不能解析的按异常行处理（与用户"异常行明确告警"要求一致）。

### 决策 7：矩阵列固定 1~当月天数

**选择**：列 = 当月天数（28~31），固定从 1 到当月最后一天。单元格为空表示当日该学生该班型无课。

**理由**：汇总表样本固定 1~31 列（即使是 2 月也铺满 31 列？样本是 9 月 30 列）。实现按当月实际天数生成列，更贴合"X 月课时汇总"语义；样本中 9 月 30 列与此一致。

### 决策 8：导出格式对齐"消课时汇总表"模版

**选择**：导出 `.xlsx` 结构：
- Row 0：标题 `"X月课时汇总"` 跨列合并（A:C + 1~N + 汇总 列）
- Row 1：表头 `序号/学生姓名/班型/1..N/汇总`
- Row 2+：每个学生×班型一行，序号自动连续从 1 开始
- 末行可选合计行（汇总列总和）

文件名 `消课表_YYYY年MM月.xlsx`。

**实现**：`XLSX.utils.aoa_to_sheet` + `ws['!merges']` 设标题合并 + `ws['!cols']` 设列宽 + `XLSX.writeFile`。

### 决策 9：月份选择交互

**选择**：导入解析后扫描所有有效行日期的年月集合：
- 1 个月 → 直接生成
- ≥2 个月 → antd `Modal` + `Radio.Group` 列出月份单选，默认选数据中最大（最近）月份，确认后生成

**理由**：用户明确要求跨月确认。默认选最近月符合"刚导完本月数据看本月"的常见场景。

## Risks / Trade-offs

- [次数列与时段÷2 不一致的行] → 以次数列为准（机构口径），告警面板可加一列"次数来源"提示从时段推算的行
- [姓名拆分数 ≠ 学生人数列] → 以姓名拆分数为准，人数列忽略；19/933 的不一致不作为异常行，仅作信息
- [班型归一化遗漏新写法] → `normalizeBanXing` 用映射表 + 正则双策略，未命中的作为异常行告警，便于用户补全
- [文本日期解析边界] → 仅支持 `YYYY.M.D`/`YYYY/M/D`/`YYYY-MM-DD` 三种，其他格式作为异常行
- [1v多拆行后班型列对每学生都是 1v3] → 保留归一化班型字符串，符合模版样本（汇总表学生列+班型列分开）
- [大月 31 列横向过宽] → 固定左侧三列（序号/学生/班型）与右侧汇总列，中间日期列横向滚动
- [序号跳号] → 完全不读源表序号，导出与界面序号自动从 1 连续递增
